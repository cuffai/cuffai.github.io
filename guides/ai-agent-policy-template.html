A one-page AI agent policy for your company

A free template for IT teams. By Andrew Sterling, Founder, Cuff AI · November 27, 2026

Most companies now have a policy for AI chat tools: don't paste client data into a public chatbot. Far fewer have one for AI agents, the tools that can read files, run commands and change code on a work computer. Claude Code, OpenAI Codex, Cursor and Gemini CLI are examples, and staff often install them on their own.

An agent policy doesn't need to be long. It needs to answer five questions that people will otherwise answer differently on every laptop. Below is a one-page template you can copy, adapt and send round this week. It is a starting point, not legal advice: adjust it to your own risks, contracts and rules.

The five questions a policy has to answer

  1. Which agents are allowed? A short approved list beats a long banned list. New tools appear every month.
  2. What may they do? Reading code is not the same as running commands or reaching the internet. Say where the line is.
  3. What must they never touch? Client files, production systems, password stores and payroll are common answers.
  4. Who can stop them, and how fast? When a tool has a serious bug, someone needs the authority and the means to turn it off.
  5. What gets recorded? If a client, auditor or insurer asks what changed, you want a record nobody has quietly edited.

The template

Replace the parts in square brackets.

[Company] AI agent policy
Owner: [name, role]   Last reviewed: [date]   Next review: [date + 6 months]

1. Scope
This policy covers AI agents: software that can read files, run commands, edit code or act in other systems on a company computer. Examples: Claude Code, OpenAI Codex, Cursor, Gemini CLI, GitHub Copilot's agent features. It does not cover chat-only tools, which [chat policy name] covers.

2. Approved agents
Only these agents may be used on company computers: [list, with the team allowed to use each].
To ask for another, email [IT contact] with the tool's name, what you want it for and who would use it. IT aims to answer within [5] business days.

3. What agents may do
By default, agents may read and suggest changes to files in the project folder you are working in. Edits are reviewed by you before they are kept.
Running commands, installing software or reaching the internet is allowed only for [teams/roles], in [named projects or folders].
Agents may never be given more access than the person running them has.

4. What agents must never touch
- Client or member files outside the project you are working on
- Production systems and production credentials
- Password managers, SSH keys and cloud keys, except through [approved method]
- [Payroll, HR, legal hold or other sensitive systems]
Never paste or store keys, passwords or client data in an agent's settings or instructions files.

5. Stopping an agent
[IT lead] and [backup] may stop or remove any agent on any company computer, at any time, without notice, when they believe it is needed to protect the company or its clients. Staff must report anything an agent did that they didn't expect to [IT contact] the same day.

6. Records
IT keeps a list of which approved agents are on which computers and what each is allowed to do. Changes to this policy, to an agent's access, and any time an agent is stopped are logged, with who did it and when. Logs are kept for [12 months / your retention period].

7. Updates
Agents must be kept on a supported version. When a security fix is announced for an approved agent, it must be updated within [3] business days, or stopped until it is.

8. Questions and exceptions
Exceptions need written approval from [role]. Questions go to [IT contact].

Making it stick

  • Start strict, then loosen. Read-only plus reviewed edits covers a lot of real work. Widen access for the teams that ask, with a reason.
  • Write it for the people using the tools. If developers think the policy is unworkable, they will route around it. Ask two of them to read the draft before you send it.
  • Know what is installed before you enforce anything. A policy for tools you can't see is a wish. Our guide on how to find the AI agents on your company's computers covers how to check.
  • Review it twice a year. The tools change faster than most policies do.
