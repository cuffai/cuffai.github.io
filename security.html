Security at Cuff AI

What protects your company's data and policies today, what isn't in place yet, and how to report a problem. Last updated November 23, 2026.

The short version

Company data is stored in Canada. Company policies are signed so a computer can't be fed a fake one, computers sign every request they send, and the audit log is hash-chained so changes to past entries show up. Cuff is a young company: we don't have a SOC 2 report or an independent penetration test yet, and we say below exactly what is and isn't in place.

Where your data lives

  • The company console's data is stored in a managed Postgres database in the AWS Canada (Central) region, in Montreal, run by Supabase.
  • Payments are handled by Stripe. Cuff never sees or stores card numbers.
  • What the desktop app sends, and what stays on the computer, is set out in the privacy policy.

What protects the company console today

  • Signed policies. Each organisation has its own Ed25519 signing key. A company policy is signed before computers receive it, so a computer can check it came from your organisation and hasn't been changed. Signing keys are stored encrypted (AES-GCM) under a master key kept in Supabase Vault.
  • Signed computers. Each enrolled computer has its own Ed25519 key and signs every request with a timestamp and a one-time value, so a captured request can't be replayed. A removed computer's key stops working.
  • Signed requests to computers. Stopping, turning off or trusting an agent, including the one-click stop for every agent the scan found, is sent as a signed request, and each computer confirms what it did.
  • A tamper-evident audit log. Every change is recorded, and each entry is chained to the one before it with a hash. Editing or deleting a past entry breaks the chain, and admins can check the chain from the console at any time. This shows tampering; it doesn't make tampering impossible.
  • Sign-in. Sign-in uses one-time email codes (no passwords to leak), single sign-on with SAML or OpenID Connect (Entra ID, Okta, Google Workspace), and automatic provisioning with SCIM. An organisation can require two-step sign-in for everyone.
  • Roles. Every action is checked against the person's role in the database itself, not only in the browser. Auditors can read without changing anything.
  • Computers that go quiet. The console's overview names any computer that has stopped checking in, since a switched-off computer and one where Cuff was stopped look the same from outside.
  • No third-party trackers. This website and the console load no advertising or analytics scripts and use self-hosted fonts. The website's visit counter stores no cookies, IP addresses or identifiers.

What isn't in place yet

We'd rather you hear this from us:

  • No independent audit yet. Cuff has no SOC 2 report, ISO 27001 certificate or CyberSecure Canada certification yet, and hasn't had an independent penetration test. These are planned.
  • Windows installers aren't code-signed yet, so Windows may warn that the publisher is unknown. Signing is being set up.
  • Enforcement against a local administrator isn't built yet. Someone with admin rights on a computer can stop Cuff on it; the console will show that computer has stopped checking in.
  • Approvals, a live activity stream and SIEM export are in development and aren't available yet.

The risks Cuff is built for

AI agents on work computers can read files, run commands and use keys. Cuff's controls line up with these widely used risk lists:

RiskWhat Cuff does about it today
Excessive agency (OWASP Top 10 for LLM Applications, 2025)One company dial caps what every agent may do, from look-only to full machine access.
Unknown AI agents ("shadow AI")The agent scan finds AI agents running on each computer, including ones started outside Cuff.
No record of what changedThe hash-chained audit log, exportable as JSON or CSV.
Agents that need stopping nowSigned stop requests per agent, or for every agent the scan found, confirmed by each computer.

Report a security problem

  • Email info.cuffai@gmail.com with "Security report" in the subject. Include what you found, how to reproduce it and what it affects.
  • We'll reply within 3 business days, keep you updated while we fix it, and credit you if you'd like.
  • If you act in good faith, stay within the issue you're reporting, don't access other people's data, don't disrupt the service and give us reasonable time to fix it before telling anyone else, we won't pursue legal action against you.
  • We don't run a paid bug bounty yet.
